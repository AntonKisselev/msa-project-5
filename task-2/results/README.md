## Выбор технологического решения
Выбор решения пал на Apache Airflow по нескольким причинам:
1. в команде нет опыта использования инструмента для пакетной обработки и компетенция не является, в данном случае, фактором
2. исходя из 1 пункта, в команде есть желание изучить именно Apache Airflow, как продукта с большим заделом. Что скажется на мотивации и соответстввенно результативности команды
3. на текущем этапе продукт не является излишни избыточен, как альтернативу можно было бы использовать простой cron, но airflow решает тоже эту задачу при не сильно бОльших затратах
4. даже на текущем этапе есть большая вероятность, что придется распределять некоторые этапы, например "извлечение client_prices" на batch порции, из-за достаточно большого кол-ва строк, что может вызвать ошибку нехватки памяти. Сделать это на cron уже будет намного более затратно, нежели на Apache Airflow
5. данное решение легко масштабируется
